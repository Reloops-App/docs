[`@reloops/mcp-server`](https://www.npmjs.com/package/@reloops/mcp-server) is an [MCP](https://modelcontextprotocol.io) server for Reloops. It wraps the same public API used by developer keys, so any MCP-compatible agent can list workspaces, search and upload assets, leave comments, manage versions, and create share links, all from a prompt.

The server runs locally as a subprocess of your MCP client (stdio transport). Your API key stays on your machine and is only ever sent to `api.reloops.app`.

<Note>
  `@reloops/mcp-server` is in beta. Tool names and behavior may still change before a stable `1.0` release.
</Note>

## Get a developer key

The server authenticates with a `reloops_live_...` developer key, the same kind used by the CLI and public API. Create one from **Manage Team → AI Agents & Developer Keys**. See [AI Agents and Developer Keys](/developers/ai-agents-and-developer-keys#create-an-ai-agent) for the full walkthrough.

## Connect your client

Every client runs the same command under the hood: `npx -y @reloops/mcp-server`, with `RELOOPS_API_KEY` set to your developer key. Pick your client below for the exact file and config.

<Tabs>
  <Tab title="Claude">
    Open **Settings → Developer → Edit Config** in Claude Desktop or Claude Code. This opens the config file below. Paste the block in, then restart the app.

    ```json claude_desktop_config.json
    {
      "mcpServers": {
        "reloops": {
          "command": "npx",
          "args": ["-y", "@reloops/mcp-server"],
          "env": {
            "RELOOPS_API_KEY": "your_key_here"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Claude Code">
    Run this in your terminal. It registers the server for you, no file editing needed.

    ```bash
    claude mcp add reloops -e RELOOPS_API_KEY=your_key_here -- npx -y @reloops/mcp-server
    ```
  </Tab>
  <Tab title="Cursor">
    Add this file to your project, or create it at `~/.cursor/mcp.json` to enable it in every project.

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "reloops": {
          "command": "npx",
          "args": ["-y", "@reloops/mcp-server"],
          "env": {
            "RELOOPS_API_KEY": "your_key_here"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="VS Code">
    Add this file to your project, or run **MCP: Add Server** from the Command Palette instead of editing it by hand.

    ```json .vscode/mcp.json
    {
      "servers": {
        "reloops": {
          "type": "stdio",
          "command": "npx",
          "args": ["-y", "@reloops/mcp-server"],
          "env": {
            "RELOOPS_API_KEY": "your_key_here"
          }
        }
      }
    }
    ```

    VS Code uses `servers` at the top level, not `mcpServers`, and needs an explicit `"type": "stdio"` field.
  </Tab>
  <Tab title="Codex CLI">
    Add this to your Codex config, or run the equivalent `codex mcp add` command instead of editing it by hand.

    ```toml ~/.codex/config.toml
    [mcp_servers.reloops]
    command = "npx"
    args = ["-y", "@reloops/mcp-server"]

    [mcp_servers.reloops.env]
    RELOOPS_API_KEY = "your_key_here"
    ```
  </Tab>
  <Tab title="Antigravity CLI">
    Add this file, or type `/mcp` in the prompt panel to manage servers interactively.

    ```json ~/.gemini/config/mcp_config.json
    {
      "mcpServers": {
        "reloops": {
          "command": "npx",
          "args": ["-y", "@reloops/mcp-server"],
          "env": {
            "RELOOPS_API_KEY": "your_key_here"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="n8n">
    Add an **MCP Client Tool** node and connect it to an AI Agent node. Fill in these fields:

    | Field | Value |
    | --- | --- |
    | Connection Type | `Command Line (STDIO)` |
    | Command | `npx` |
    | Arguments | `-y @reloops/mcp-server` |
    | Environment Variables | `RELOOPS_API_KEY=your_key_here` |

    Your agent can now call the same tools listed below from inside the workflow.
  </Tab>
</Tabs>

Any other MCP client that reads a JSON config file will use the same underlying command: `npx -y @reloops/mcp-server`, with `RELOOPS_API_KEY` set under `env`. Adjust the top-level key and file path for that client's own format.

## Validate

After connecting, ask your agent something like *"List my Reloops workspaces"* or *"What's still waiting on approval?"*. A structured response back from your workspace confirms the connection is working.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Tools not appearing in your client">
    - Confirm the config file has valid JSON (or TOML for Codex CLI): a missing comma or brace stops the whole file from loading, not just the `reloops` entry.
    - Restart the client after editing its config. Most clients only read MCP config on startup.
    - Run `npx -y @reloops/mcp-server` directly in a terminal. If it hangs waiting on stdin without printing an error, the package installed and started correctly, the issue is in your client's config, not the server.
  </Accordion>
  <Accordion title="Authentication or permission errors">
    - Confirm `RELOOPS_API_KEY` is set in the `env` block for your client, not just in your shell, most clients launch the server as a separate process that doesn't inherit your shell's environment.
    - Check the key hasn't been revoked: go to **Manage Team → AI Agents & Developer Keys** and confirm the agent is still listed.
    - Make sure the key is scoped to the workspace you're asking about. A developer key only sees what its organization can access.
  </Accordion>
  <Accordion title="npx fails or can't find the package">
    - Confirm Node.js is installed and `npx` is on your `PATH` (`npx --version` in a terminal).
    - The first run downloads the package fresh each time unless it's cached. If you're on a slow or restricted network, this can time out, try `npm install -g @reloops/mcp-server` and pointing `command` at the globally installed binary instead of `npx`.
  </Accordion>
</AccordionGroup>

Need a scriptable path instead of an agent? See [Reloops CLI and Public API](/developers/reloops-cli-and-public-api).
